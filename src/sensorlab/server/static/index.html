01Overview

Held-out performance of the deployed pipeline. Every number below is measured on test runs the model never saw, with thresholds fixed on validation.

02Acceptance criteria

Release gates from the runbook, evaluated on this process at start-up. A failed gate means the model is not to be trusted for that purpose until retrained.

03Ownership

Who decides each number. Cost and horizon belong to the business; changing one is a retrain, not an edit on the saved model.

04Detection benchmark

Three detectors, one false-alarm budget. FAR observed is the calibration check: a threshold set on validation should reproduce roughly the target on test.

05Decision layer

Expected cost across thresholds on the test runs. The dotted line is the threshold the model shipped with (chosen on validation); the solid one is the oracle optimum on test. The gap is the price of not peeking.

06Held-out runs

One row per test run: when the fault started, when the confirmed alarm came, what was diagnosed at that moment and what the operator was told to do. Click a row to inspect it.

Run —

Recommended action along the run

07Diagnosis

Which sensor drives each fault, by mean |SHAP| aggregated per sensor. The table a process engineer signs off on.

08Drift

Population Stability Index per sensor on the normal held-out runs versus the training reference. Thresholds sit above the plant's own run-to-run noise floor. Simulate a recalibration to see the monitor react.

09Score a batch

Upload a CSV or parquet of sensor rows (training sensor columns, optional run_id). Returns per-sample scores, confirmed alarms, diagnosis, RUL interval and action, and logs the call below.

This is the static build (GitHub Pages): there is no scoring backend behind it. Score a batch with the CLI, or run the API locally.

pip install "sensorlab @ git+https://github.com/Gemmagf/sensorlab"
sensorlab train                                  # or use your own models/pipeline.joblib
sensorlab score --input batch.csv --output scored.csv --drift
sensorlab serve                                  # same dashboard with live upload-and-score at http://127.0.0.1:8000

10Audit log

Scoring calls made against this process, newest first.

Not available in the static build: the audit log lives in the process that scores (sensorlab serve).
