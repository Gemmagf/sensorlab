09Score a batch

Upload a CSV or parquet of sensor rows (training sensor columns, optional run_id). Returns per-sample scores, confirmed alarms, diagnosis, RUL interval and action, and logs the call below.

This is the static build (GitHub Pages): there is no scoring backend behind it. Score a batch with the CLI, or run the API locally.

pip install "sensorlab @ git+https://github.com/Gemmagf/sensorlab"

sensorlab serve                                  # same dashboard with live upload-and-score at http://127.0.0.1:8000

1 · What you are looking at

A continuous chemical plant emits dozens of correlated sensor streams. The pipeline behind this page turns them into an operational decision in four layers. Everything shown here is measured on held-out test runs the model never saw, with thresholds fixed on validation.

LayerQuestionHow
DetectionIs something wrong right now?Three detectors trained on normal operation only (PCA T²/Q, Isolation Forest, LSTM autoencoder). Each gives an anomaly score per sample.
DiagnosisWhich fault, and which sensor drives it?XGBoost on window features per sensor, explained with SHAP aggregated per sensor.
Remaining useful lifeHow long until I must intervene?Quantile gradient boosting (p10 / p50 / p90) with a conformal margin so the 80 % interval really covers 80 %.
DecisionWhat should the operator do?A cost model picks the operating threshold; confirmed alarm × diagnosis × RUL → one of four actions.

3 · Actions and thresholds

ActionMeaningRule
waitNothing to do.No confirmed alarm.
investigateThe detector fired but the classifier reads Normal: a novel or not-yet-recognisable pattern.Alarm and predicted fault = Normal.
schedule_maintenanceFault identified, time to plan.Alarm, fault, RUL median above the horizon.
intervene_nowFault identified, horizon exceeded.Alarm, fault, RUL median at or below the horizon.

An alarm is confirmed only after three consecutive samples (9 minutes) above the operating threshold within the same run. Each detector has two thresholds: the FAR threshold (1 % of validation-normal samples above it, used for the benchmark) and the operating threshold (minimum expected cost on the validation runs, used for alarms). With the reference cost mix, where a missed fault costs 50× a false alarm, the operating threshold sits well below the FAR threshold on purpose.

RUL is a ranking of urgency: p50 is the median minutes until the end of the fault episode, p10/p90 an 80 % interval calibrated on validation. On the synthetic benchmark it is a function of time since onset, not a physical time-to-failure.

4 · Drift

Each sensor's distribution in a batch is compared with the training-normal reference (Population Stability Index). Thresholds sit per sensor above the plant's own run-to-run noise floor, measured leave-one-run-out at training time.

stable the data is what the model was trained on · watch investigate (recalibration, new operating point) · alert do not trust alarms driven by those sensors until retrained. A batch containing a real fault also shows as drift, so check on known-normal periods.

5 · Score your own data

pip install "sensorlab @ git+https://github.com/Gemmagf/sensorlab"
sensorlab train                                    # or use your own models/pipeline.joblib
sensorlab score --input batch.csv --output scored.csv --drift
sensorlab serve                                    # this page with live upload-and-score

Input: one row per sample in time order, the training sensor columns (XMEAS(1) … XMV(11); xmeas_1 style is accepted), an optional run_id column with the rows of one run contiguous, no missing values.

Output: your rows plus score_<detector>, primary_score, threshold, above_threshold, alarm, fault_id_pred, fault_name_pred, fault_confidence, rul_p10_min, rul_p50_min, rul_p90_min, action.

6 · Bringing your own plant

Only the loader knows about the data source. Return a TEPDataset (sensor matrix, contiguous run ids, per-run onsets and fault labels), call validate(), and train the pipeline on it. Decide up front the sample interval, how many normal runs you have (detectors and the drift reference learn from those only) and the cost mix.

Full details: the user guide (install, CLI, Python API, FAQ) and the operations runbook (what to do when a gate fails or drift alerts, retraining cadence).
